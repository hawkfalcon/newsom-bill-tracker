# Newsom Bill Watch

A static GitHub Pages site that lists every California bill **Gov. Gavin Newsom
signs or vetoes** in the current legislative session — plus the bills still
sitting on his desk awaiting action. Each bill links to its page on
[CalMatters' Digital Democracy](https://calmatters.digitaldemocracy.org/bills).

**Live demo of the workflow:** the data and `index.html` in this repo were
generated by `scripts/fetch_bills.py` on 2026-09-11 for the 2025–26 session.

## How it works

1. **`scripts/fetch_bills.py`** — pulls the current session's full bill list
   from the official [LegInfo](https://leginfo.legislature.ca.gov) site, keeps
   every bill whose status is *Chaptered* (signed), *Vetoed*, or *Enrolled*
   (awaiting the Governor), then fetches each bill's status page to get the
   exact action date and chapter number. Outputs `data/bills.json`.

   > LegInfo is the source of truth for **sign / veto status**. Digital
   > Democracy is used as the rich detail page we link out to.

2. **`scripts/build_site.py`** — inlines `data/bills.json` into
   `site/template.html` and writes a single self-contained `index.html`
   (no server, no build step, no external requests).

3. **`.github/workflows/update.yml`** — a GitHub Actions workflow that runs the
   two scripts **daily** (and on demand via "Run workflow") and commits the
   refreshed files back to the repo.

## Digital Democracy links

The link format is deterministic:

```
https://calmatters.digitaldemocracy.org/bills/ca_<lowercased-leginfo-bill-id>
```

e.g. LegInfo `202520260AB302` → `ca_202520260ab302` →
<https://calmatters.digitaldemocracy.org/bills/ca_202520260ab302>

## Deploy to GitHub Pages

1. Create a repo and push these files (keep this structure):

   ```
   .
   ├── .github/workflows/update.yml
   ├── index.html              # generated (self-contained)
   ├── data/bills.json         # generated
   ├── scripts/fetch_bills.py
   ├── scripts/build_site.py
   └── site/template.html
   ```

2. In the repo: **Settings → Pages → Build and deployment → Source:
   "Deploy from a branch" → Branch: `main`, folder `/ (root)` → Save.**

3. To refresh the data immediately: **Actions → "Refresh bill data" → Run workflow.**

## Run locally

```bash
pip install requests
python scripts/fetch_bills.py --out data/bills.json   # ~2 min
python scripts/build_site.py --data data/bills.json --template site/template.html --out index.html
python -m http.server 8000   # then open http://localhost:8000
```

## Notes & caveats

- **Current session only.** The scraper defaults to session `20252026`
  (`--session` flag). Change it when a new two-year cycle begins.
- **"Awaiting action"** = bills LegInfo lists as *Enrolled*. During the
  September signing window this can be a large list that shrinks as the
  Governor acts (last day to act on 2025–26 session bills: Sept 30, 2026).
- LegInfo occasionally serves a redirect or lags a few hours on the newest
  chaptering/veto lines; the scraper retries transient failures and falls back
  to the "Chaptered Date" summary field, so a freshly-signed bill may briefly
  appear without its chapter number.
- This is an unofficial tracker. It is not affiliated with the Governor's
  office, the California Legislature, or CalMatters.
